# SRV Helper

![SRV Helper](assets/srv-helper-banner.png)

**SRV Helper** پنل ترمینالی برای مدیریت سرور Ubuntu و Debian است. وضعیت CPU، رم و دیسک را در یک نگاه ببینید، گواهی SSL بگیرید و DNS و میرور APT را از روی سرور خودتان بسنجید.

[راهنمای انگلیسی](README_EN.md)

- توسعه‌دهنده: **AmirTN9**
- GitHub: https://github.com/Amirtn9/srvhelper
- نسخه: `1.0.0`
- سیستم‌های پشتیبانی‌شده: Ubuntu و Debian

## نصب و اجرای فوری با Bash

اگر با کاربر `root` وارد سرور شده‌اید، در Bash این دستور نصب‌کننده را از GitHub اجرا می‌کند و پس از تأیید نصب، منو را باز می‌کند:

```bash
bash <(curl --proto '=https' --proto-redir '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/Amirtn9/srvhelper/main/install.sh) --launch
```

اگر کاربر عادی هستید، ابتدا با `sudo -i` وارد پوستهٔ روت شوید. برای دیدن فایل قبل از اجرا، از [روش دانلود جداگانه](#اجرای-آنلاین-از-ترمینال) استفاده کنید.

## داشبورد در یک نگاه

```text
  SRV HELPER  v1.0.0
  vps01 / debian 13
  CPU   [####------------]  24%  4 logical CPUs
  RAM   [########--------]  50%  Memory in use
  Disk  [###-------------]  19%  Root filesystem
```

در **Abzar System → Vaziat server**، برای نمونه‌گیری دوباره `R` و سپس Enter بزنید. درصد CPU از تغییر شمارنده‌های کرنل طی یک نمونهٔ کوتاه به دست می‌آید.

## Server Doctor

گزینهٔ **Server Doctor** در منوی اصلی یا دستور زیر، وضعیت دیسک، DNS، مسیر IPv4 و IPv6، کش APT، SSH و انقضای گواهی را بررسی می‌کند. گزارش نام میزبان، IP و دامنه‌های گواهی را چاپ نمی‌کند و تنظیمات سرور را تغییر نمی‌دهد.

```bash
srv-helper --doctor
```

برای جزئیات DNS هر رابط از بخش وضعیت DNS استفاده کنید. گزارش IPv4 و IPv6 وجود مسیر را بررسی می‌کند.

## ابزارهای پایش و عیب‌یابی

- **Live Server Dashboard** در بخش ابزارهای سیستم، CPU، تاریخچهٔ مصرف آن، RAM، دیسک، Swap و نرخ دریافت و ارسال رابط شبکه را نشان می‌دهد. با `P` مکث کنید، با `N` رابط را عوض کنید و با `Q` برگردید. دستور مستقیم آن `srv-helper --live` است.
- **Doctor Compare** در منوی Server Doctor، گزارش قبل را برای همان نشست نگه می‌دارد و تغییرات گزارش بعد را نشان می‌دهد.
- **Mirror Lab** در منوی APT، تاریخ ساخت متادیتای Release و سرعت نمونه‌ای تا ۱۲۸ KiB از فهرست بسته‌ها را گزارش می‌کند. اگر سرور درخواست Range را نپذیرد، نتیجهٔ سرعت نمایش داده نمی‌شود.
- **Certificate Dashboard** روزهای باقی‌مانده و تطابق کپی مقصد با نسخهٔ Certbot را نشان می‌دهد. اگر systemd نتیجهٔ آخرین اجرای سرویس Certbot را ثبت کرده باشد، همان نتیجه هم نمایش داده می‌شود.

## بکاپ و انتقال بین دو VPS

روی **سرور جدید** به‌عنوان root وارد **Backup va Enteghal Server** شوید. نسخهٔ Ubuntu و معماری هر دو سرور باید دقیقاً یکی باشند. روی مقصد `apt install openssh-client gnupg` و روی مبدأ، SSH و دسترسی root یا `sudo -n` لازم‌اند. رمز SSH را فقط در prompt خود OpenSSH وارد کنید.

اثر انگشت میزبان را از کنسول مورد اعتماد **سرور قدیمی** بگیرید:

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

- **Backup** از فایل‌سیستم روت و volumeهای محلی پشتیبانی‌شده، فهرست پکیج‌ها، سرویس‌ها و mountها و dump منطقی دیتابیس‌های پشتیبانی‌شده آرشیو رمزگذاری‌شده می‌سازد. مسیر فایل بکاپ در گزارش پایانی چاپ می‌شود. برای سازگاری داده‌ها، قبل از شروع نوشتن برنامه‌ها روی مبدأ را متوقف کنید. dump MySQL/MariaDB تا پایان گرفتن dump، نوشتن را قفل می‌کند.
- **Backup & Restore** بعد از ساخت و بررسی بکاپ، محتوای `/srv`، `/var/www` و پوشه‌های برنامه و کاربر در `/opt` و `/home` را در مقصد خالی و داده‌های دیتابیس را بازیابی می‌کند. پوشه‌های غیرخالی `/opt` و `/home` در پیش‌نمایش کنار گذاشته می‌شوند. پوشهٔ `.ssh` کاربران فقط در بکاپ می‌ماند. نام و شناسهٔ عددی مالک و گروه فایل‌های منتقل‌شده باید در مقصد یکسان باشند. یک کلاستر آنلاین PostgreSQL با major یکسان و بدون tablespace سفارشی برای بازیابی خودکار پشتیبانی می‌شود. در مقصد بدون PostgreSQL، در صورت دسترسی بستهٔ متناظر در APT، خود برنامه آن را نصب می‌کند. MySQL/MariaDB به سرویس خالی با همان نسخه نیاز دارد و تعریف حساب‌های برنامه و grantها در فایل SQL جداگانه‌ای ذخیره می‌شوند. برای بکاپ‌های جدید، در صورت تأیید جداگانه و نبود حساب همنام در مقصد، ویزارد آن‌ها را هم وارد می‌کند.
- **Restore az archive** با رمزگشایی و کنترل checksum، بازیابی از بکاپ خودتان را بدون اتصال به سرور قدیمی انجام می‌دهد. از آرشیوهای ناشناس استفاده نکنید.
- آرشیو فایل‌محور است. فایل‌های volumeهای محلی شناسایی‌شده در آن می‌آیند، اما جدول پارتیشن، bootloader، mountهای شبکه و فایل‌سیستم‌های موقت خارج از آن‌اند. سرویس‌های ناشناخته، Docker، پکیج‌ها، شبکه، SSH و تنظیمات سیستم خودکار روی مقصد فعال نمی‌شوند. برای کپی کل دیسک و سرویس‌های ناشناخته باید از ایمیج آفلاین و ابزار بازیابی میزبان استفاده کنید.
- اگر بازیابی وسط import شکست بخورد، مقصد می‌تواند بخشی از تغییر را داشته باشد و ویزارد موفقیت گزارش نمی‌کند. بکاپ رمزگذاری‌شده برای ادامهٔ بازیابی حفظ می‌شود. برای بررسی دستی، در یک پوشهٔ root-only آرشیو را باز کنید و `sha256sum -c SHA256SUMS` بزنید. فایل `root.tar.gz` را مستقیماً روی روت سرور در حال اجرا باز نکنید.

## بخش‌های اصلی

### ۱. SSL و گواهی‌ها

- **Single:** یک دامنه و یک گواهی.
- **SAN:** دو تا ۲۵ دامنه داخل یک گواهی.
- **Batch:** برای هر دامنه یک گواهی مستقل؛ حداکثر ۵۰ دامنه. اگر DNS یک دامنه آماده نباشد، آن دامنه رد می‌شود و بررسی دامنه بعدی ادامه پیدا می‌کند.
- اعتبارسنجی HTTP-01 به روش Standalone یا Webroot.
- اصلاح حروف بزرگ و کوچک، حذف فاصله‌های ابتدا و انتها و تشخیص دامنه تکراری.
- بررسی DNS قبل از ارسال درخواست صدور.
- ذخیره در مسیر Pasarguard، مسیر Root یا مسیر دلخواه.
- تنظیم دسترسی کلید خصوصی و انتقال مجدد گواهی پس از تمدید خودکار.
- نمایش گواهی‌ها، بررسی SAN و تست تمدید.

### ۲. DNS و میرور

- DNSهای ایرانی، سرویس‌دهنده‌های اینترنت و DNSهای بین‌المللی.
- تست DNSها و مرتب‌سازی بر اساس پاسخ موفق و زمان پاسخ.
- میرورهای منطقه‌ای ایران، اروپا و آمریکا. فهرست ایران شامل آروان، ایران‌سرور، پیشگامان، مبین‌هاست، فاماسرور و LinuxMirrors است. گزینه‌ها بسته به توزیع و معماری فرق دارند.
- از **Shabake → Mirror APT → Iran** تست را شروع کنید. حداکثر ۱۰ میرور سازگار بر اساس زمان دریافت فایل `Release` در میلی‌ثانیه نمایش داده می‌شوند. شمارهٔ گزینه را بزنید و Enter بزنید تا همان میرور برای اعمال انتخاب شود. اگر تعداد گزینه‌های معتبر کمتر باشد، همان تعداد نمایش داده می‌شود. در کنار زمان، نرخ نمونهٔ دریافت همان فایل در KiB/s نمایش داده می‌شود. هر دو به فایل کوچک Release مربوط‌اند.
- بررسی فایل Release قبل از انتخاب میرور.
- پیش‌نمایش تغییر و تاریخچهٔ قابل انتخاب برای بازگردانی DNS و APT. برای میرور، شاخه‌های فعال که قرار است جابه‌جا شوند هم بررسی می‌شوند.

### ۳. تنظیم هوشمند سرور

- تشخیص منطقه سرور در صورت دسترسی به سرویس تشخیص موقعیت IP؛ انتخاب دستی هم وجود دارد.
- تست DNS و انتخاب گزینه‌های پاسخ‌گو.
- تست میرورها و انتخاب توسط کاربر از فهرست رتبه‌بندی‌شده.
- اجرای `apt-get update` پس از انتخاب میرور.
- فعال‌سازی BBR فقط در صورت پشتیبانی کرنل.
- نمایش گزارش نهایی عملیات. ارتقای خودکار پکیج‌ها انجام نمی‌شود.

### ۴. سرویس‌ها و ابزارهای سرور

- کنترل سرویس‌های تونل: وضعیت، Start، Stop، Restart و Log.
- مدیریت Swap و ZRAM.
- پروفایل‌های TCP شامل BBR، Hybla و Cubic.
- Fail2ban برای محافظت SSH و اسکن فقط‌خواندنی ClamAV.
- نصب Cockpit برای مانیتورینگ.
- اطلاعات سرور، پورت‌های باز، Route، DNS، IPv6، Ping، تست MTU و بررسی تنظیمات SSH.

## نصب آسان از GitHub

روی سرور Ubuntu یا Debian، با کاربری که دسترسی `sudo` دارد:

```bash
git clone --depth 1 https://github.com/Amirtn9/srvhelper.git &&
  cd srvhelper &&
  sudo bash install.sh --launch
```

نصب‌کننده منبع و مقصد را نشان می‌دهد، برای ادامه تأیید می‌گیرد و پیشرفت را در چهار مرحله نمایش می‌دهد. نصب در `/opt/srv-helper` انجام می‌شود. برای اجرای بعدی روی سرور از `sudo srv-helper` استفاده کنید.

| گزینه | کاربرد |
| --- | --- |
| `--check` | بررسی پیش‌نیازها و صحت نحوی فایل‌ها بدون اعمال نصب |
| `--yes` | نصب بدون سؤال برای خودکارسازی |
| `--launch` | باز کردن منوی برنامه پس از نصب در همان ترمینال |

### به‌روزرسانی پوشهٔ موجود

اگر قبلاً پروژه را در `~/srvhelper` گرفته‌اید، همان نسخه را به‌روز کنید. اگر ادغام سریع ممکن نباشد، دستور نصب اجرا نمی‌شود.

```bash
cd ~/srvhelper &&
  git pull --ff-only &&
  bash install.sh --check &&
  sudo bash install.sh --launch
```

## اجرای آنلاین از ترمینال

این مسیر به دسترسی HTTPS به GitHub نیاز دارد. برای مشاهدهٔ اختیاری فایل نصب‌کننده، پس از دانلود آن را با `less "$installer/install.sh"` باز کنید و با `q` برگردید.

```bash
installer=$(mktemp -d)
curl --proto '=https' --proto-redir '=https' --tlsv1.2 -fL \
  https://raw.githubusercontent.com/Amirtn9/srvhelper/main/install.sh \
  -o "$installer/install.sh" &&
  sudo bash "$installer/install.sh" --launch
```

نصب‌کنندهٔ آنلاین فایل‌های برنامه را از شاخهٔ `main` دریافت می‌کند. برای نصب تکرارپذیر، یک کامیت مشخص را از GitHub دریافت کنید و `bash install.sh` را از پوشهٔ همان کامیت اجرا کنید. برای اجرای مستقیم بدون نصب سیستمی، از همان پوشه `bash srv-helper.sh` را اجرا کنید. عملیات مدیریتی به دسترسی روت نیاز دارند.

## نصب روی سرورهای ایران

اگر سرور به GitHub دسترسی دارد، از همان روش نصب آسان استفاده کنید. اگر دانلود روی سرور ناموفق بود، [آرشیو ZIP پروژه](https://github.com/Amirtn9/srvhelper/archive/refs/heads/main.zip) را روی دستگاهی که به GitHub دسترسی دارد بگیرید و با SSH منتقل کنید. در مثال زیر، `USER` و `SERVER_IP` را جایگزین کنید.

```bash
scp srvhelper-main.zip USER@SERVER_IP:~/
ssh USER@SERVER_IP
```

سپس روی سرور اجرا کنید:

```bash
unzip srvhelper-main.zip
cd srvhelper-main
bash install.sh --check
sudo bash install.sh --launch
```

در این روش فایل‌های برنامه از همان پوشه خوانده می‌شوند. اگر `unzip` روی سرور موجود نیست، ابتدا آرشیو را روی دستگاه خود باز کنید و پوشه را با `scp -r` منتقل کنید. اگر گزارش نصب نشان می‌دهد بسته‌ای کم است، ابتدا با APT سرور آن را نصب کنید. دسترسی به مخازن بسته‌های Ubuntu یا Debian برای نصب بسته‌های جاافتاده لازم است، حتی اگر فایل‌های برنامه را با SCP منتقل کرده باشید.

پس از نصب، از **Shabake → DNS** یا **Mirror** می‌توانید گزینه‌های ایران را از روی خود سرور آزمایش کنید. در Ubuntu روی معماری‌های غیر x86، انتخاب خودکار APT از آرشیو رسمی Ports استفاده می‌کند. پیش از اعمال تغییرات شبکه، دسترسی کنسول میزبان را آماده نگه دارید.

## بررسی DNS اعمال‌شده

روی سرور دارای `systemd-resolved`، بعد از اعمال پروفایل، `/etc/resolv.conf` به stub سیستم اشاره می‌کند و معمولاً `127.0.0.53` نشان می‌دهد. آدرس‌های upstream مانند `8.8.8.8` و `8.8.4.4` را در خروجی `resolvectl dns` و منوی وضعیت DNS ببینید. در حالت فایل استاتیک، خود `/etc/resolv.conf` آدرس‌های جدید را نشان می‌دهد. اگر VPN یا شبکهٔ دیگری route پیش‌فرض DNS متداخل داشته باشد، برنامه اعمال را موفق اعلام نمی‌کند و تنظیم قبلی را برمی‌گرداند.

## راهنمای رفع مشکل صدور SSL

برای صدور گواهی با روش HTTP-01:

۱. دامنه را به شکل `pl24.pingyar.com` وارد کنید. اگر آدرس کامل `http(s)://` وارد شود، نام دامنه از آن استخراج می‌شود؛ IP و پورت دلخواه پذیرفته نمی‌شوند.

۲. رکورد عمومی A باید به IP همین VPS اشاره کند. اگر رکورد AAAA دارید، IPv6 آن هم باید به همین سرور برسد؛ در غیر این صورت AAAA اشتباه را اصلاح یا حذف کنید.

۳. پورت TCP شماره ۸۰ باید از اینترنت قابل دسترسی باشد.

۴. اگر وب‌سرور از پورت ۸۰ استفاده می‌کند، روش Webroot را انتخاب و مسیر واقعی ریشه سایت همان دامنه را وارد کنید.

۵. اگر CDN یا Proxy فعال است، مسیر `/.well-known/acme-challenge/` باید به سرور منتقل شود.

پورت‌های ۳۱۰۴ تا ۳۱۱۰ به‌تنهایی با صدور HTTP-01 تداخل ندارند؛ پورت مهم برای این روش، TCP شماره ۸۰ است.

گواهی Wildcard با روش HTTP-01 صادر نمی‌شود و به اعتبارسنجی DNS-01 نیاز دارد.

## کلیدهای بازگشت و خروج

- در منوهای تعاملی با کلیدهای بالا و پایین گزینه را مشخص کنید و Enter بزنید. Home و End به ابتدا و انتهای فهرست می‌روند. شمارهٔ گزینه را هم می‌توانید وارد کنید و Enter بزنید.
- در این منوها Esc به منوی قبلی برمی‌گردد و Q برنامه را می‌بندد. در ورودی‌های متنی از `back` و `exit` استفاده کنید.
- برای استفاده از منوی خطی، برنامه را با `SRV_PLAIN_MENU=1` اجرا کنید. ورودی پایپ‌شده به‌صورت خودکار از منوی شماره‌ای استفاده می‌کند.
- منوهای برنامه فینگلیش و پیام‌های نصب‌کننده انگلیسی هستند. هر دو از نویسه‌های ASCII استفاده می‌کنند.

## نکات ایمنی

- تغییرات سیستمی به دسترسی Root و تأیید کاربر نیاز دارند.
- روی سرورهای دارای `ssh.socket`، مدیریت پورت از منوی برنامه غیرفعال است. تنظیم شنونده را از کنسول میزبان انجام دهید.
- قبل از تغییر DNS و APT نسخه پشتیبان ساخته می‌شود و در صورت شکست APT Update، تنظیمات قبلی بازمی‌گردند.
- تغییر DNS روی `systemd-resolved` فعال یا فایل استاتیک تک‌سرور پشتیبانی می‌شود. برای فایل‌های تحت مالکیت NetworkManager، dhclient یا resolvconf، تنظیم را در همان مدیر شبکه انجام دهید.
- Smart Setup پکیج‌ها را به‌صورت خودکار Upgrade نمی‌کند.
- پیش از تغییر تنظیمات شبکه VPS ریموت، دسترسی کنسول خارج از SSH را حفظ کنید.
